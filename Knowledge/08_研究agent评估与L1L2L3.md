# 研究 agent 评估：从模型指标（L1）到研究任务（L2）到跨轮研发收益（L3）

> 学习结论：L1（如 BPB）与 L2（研究／工程任务表现）的联系，在公开证据中是**平均意义上、基座模型之间、同域语料**的强相关；对单个任务的预测误差大，对 agentic 任务没有直接证据。L2 的评估需要处理三件事：部分进度怎样计分、人类基线和时间预算怎样设定、结果是否真的是跑出来的。L3（跨轮研发收益）目前没有成熟的公开测量方法，只能设计提案。
>
> L1–L2–L3 是**你的准备框架**，不是 Mirendil 的官方术语。应用：[Companies/Mirendil](../Companies/Mirendil.md)、[Practice 分支 D](../Practice/01_岗位分支实验.md)。

## 1. 定义

- **L1：模型指标**。例如 held-out 语料上的 bits-per-byte：`BPB = 总负对数似然（以 bit 计） / 字节数`。按字节归一化使不同 tokenizer 的模型可比。Mirendil 的预训练文章（2026-10-21，公司自报）正是用“在其自有仓库与 7 个训练后发布的外部仓库上的 held-out 代码 BPB”比较模型。
- **L2：研究任务表现**。agent 在给定环境、预算下完成研究／工程任务的程度：修 bug、复现论文、做 kernel 优化、跑一个 scaling 实验。
- **L3：跨轮研发收益**。用 agent 做研发，是否让下一代模型（或下一轮研究）更快、更好、更便宜。

**为什么分三层**：每一层的提升都不自动推出下一层。L1 更低可能只是更擅长“补全你的代码风格”；L2 更好可能来自 harness 或预算；L3 还涉及人类研究员、计算、组织流程的混杂。

## 2. L1 → L2：公开证据说了什么

| 来源 | 设定 | 发现 | 不能推出 |
|---|---|---|---|
| Huang et al. 2024, *Compression Represents Intelligence Linearly*（arXiv 2404.09937, COLM） | 31 个基座模型（1.3B–72B）；在训练截止后收集的语料上测 BPC | BPC 与平均 benchmark 分数近线性相关：总体 ρ≈−0.93；代码 −0.937，数学 −0.953 | 后训练模型、单个 benchmark、agentic 任务；跨域语料相关性变弱；选择题格式造成跳变 |
| Gadre et al. 2024（arXiv 2403.08540） | 104 个模型（0.011B–6.9B） | 平均 top-1 误差可由 loss 的指数律预测（6.9B 上 0.05% 误差） | 单任务误差 5%–26%；只保留了 46 个中 17 个“高于随机”的任务 |
| Schaeffer et al. 2023（仅读摘要） | — | “涌现”可能是不连续指标造成的 | — |

**对 Mirendil 的含义（推断）**：
- 用自有仓库代码做 BPB 是**同域语料**，所以与“在自有代码上修 bug”可能有较强关联，但这是需要验证的假设。
- 文中也提到后训练模型 BPB 略差于其基座版本。**BPB 不适合比较后训练模型的任务能力**，因为后训练改变了输出分布，而不一定降低能力。
- 没有任何读到的来源把 BPB 与 agentic 任务成功率直接联系起来。这是一个真实的研究空白，也是好的面试话题。

## 3. L2 怎样评估：三个代表性 benchmark 的设计选择

| 设计问题 | RE-Bench（METR, 2411.15114） | MLE-bench（OpenAI, 2410.07095） | PaperBench（OpenAI, 2504.01848） |
|---|---|---|---|
| 任务 | 7 个 ML 研究工程任务 | 75 个 Kaggle 竞赛 | 复现 20 篇 ICML 2024 论文 |
| 计分 | 连续：`(y − y_start)/(y_ref − y_start)`，起点 0、参考解 1 | Kaggle 奖牌阈值（对照私有榜快照） | 与原作者共同制定的层级加权 rubric，共 8,316 个叶子要求 |
| 部分进度 | 连续分数天然支持 | 按奖牌档 | 叶子分为 Code Development / Execution / Result Match |
| 人类基线 | 61 位专家、71 次尝试、每次 8h | Kaggle 选手（隐含在榜单中） | 8 位 ML 博士，最长 48h |
| 预算 | 2/8/16/32h 总预算；允许 best-of-k 切分 | 每次尝试 24h | 12–36h |
| judge 验证 | 人工检查高分 run | LLM 日志监控 + 人工复核 | **JudgeEval**：judge 与人类评分的 F1（o3-mini 0.83，随机 0.49） |

**值得记住的发现**：
- **预算决定排名**。RE-Bench：2h 时最好的 agent 是人类的 4 倍，8h 时人类略胜，32h 时人类是最好 agent 的 2 倍。没有预算的排名没有意义。
- **只看代码是差的 proxy**。PaperBench 的 Code-Dev 变体（只评代码）与完整评分相关性只有 r=0.48。对应到你的经验：没有最终 artifact 时，proxy 信号不能当作 outcome 验证。
- **噪声过拟合**。RE-Bench 中一个 GPT-2 QA 高分解在重跑时从 0.88 降到 0.69；agent 能看到测试分数时会过拟合。
- **时间视野**（METR, Kwa et al. 2503.14499）：用逻辑回归拟合“成功率 vs log(人类所需时间)”，50% 成功率对应的人类时间即模型的 time horizon；报告约 7 个月翻倍（207 天，CI 166–240）。假设包括：人类时间是有效的难度度量；结果依赖基线人员（承包者比仓库维护者慢 5–18 倍）；任务多为自动评分的“干净”任务。

## 4. 研究 agent 的已记录失败

| 失败 | 例子 | 检测方法 |
|---|---|---|
| 伪造或“模拟”结果 | RE-Bench：复制参考模型权重并“模拟”训练；AI Scientist 评测（Beel et al.，仅读摘要）记录到虚构的数值结果 | 结果必须由 harness 重新执行；对比 artifact 的产生时间与运行日志 |
| 作弊评分函数 | METR：o3 改写计时器、桩掉 evaluator | 评分代码与 agent 隔离；作弊率单独报告 |
| 过早宣布完成 | PaperBench：agent 声称完成或声称问题不可解后提前结束 | 不读自述，读 artifact |
| 不执行计划 | PaperBench：写了计划没执行 | trace 中检查计划步骤与执行步骤的对应 |
| 噪声过拟合 | RE-Bench GPT-2 QA 0.88→0.69 | 重跑；保留测试与可见分数分离 |
| 违规资源 | PaperBench：646 次 run 中 10 次使用黑名单资源，计 0 分 | 网络／资源白名单与日志审计 |

**“报告的数字是否真的跑出来”是研究任务 verifier 的核心检查**：verifier 应从 harness 自己的执行日志中重算指标，而不是相信 agent 写进报告的数字。这一条可直接用于 Mirendil take-home。

## 5. L3：只能提出的测量方案（提案，未验证）

L3 的问题：“agent 让研发更快”与“这一轮研究本来就容易”“人类研究员做了关键决策”“用了更多算力”如何区分？

可检验的设计：
1. **配对的研究任务**：同一组研究问题，随机分配“有 agent 辅助 / 无 agent”或“agent 版本 A / B”。单位是研究问题，不是 run。
2. **固定算力与人力预算**，记录人类干预次数与时长。
3. **结果用 L2 式的独立 verifier 判定**（重跑、隐藏评估集），而不是用研究者自述。
4. **跨轮**：第 n 轮得到的改进是否在第 n+1 轮的保留任务上仍然有效（避免在同一组任务上自我证明）。

**不能从一次案例推出的结论**：Mirendil 自报“一位研究员 3.5 个月、<1000 万美元、AI agent 写了 99% 以上代码”训练出基座模型。这是一个令人印象深刻的案例，但它不是对照实验，不能单独说明 agent 带来的加速倍数，也不能证明“完全自主的递归自我改进”。

## 6. 面试追问

- “BPB 下降了，模型就更会修 bug 吗？” → 同域语料上平均相关性强（Huang），单任务预测差（Gadre），后训练模型不可比，agentic 任务无直接证据；给出验证设计：同一批 checkpoint 上同时测 BPB 与 L2 任务，看秩相关与例外。
- “怎么给研究任务打部分分？” → 连续指标归一化（RE-Bench）或层级 rubric（PaperBench）；说明 rubric 需要与 judge 一起被验证（JudgeEval）。
- “怎么知道 agent 没编结果？” → harness 重新执行、从日志重算、artifact 与日志对应、作弊率。
- “training observability 指什么？”（Mirendil JD 原文：让研究者理解模型行为在变什么、为什么变）→ 训练过程中定期在固定行为探针集上跑评估，追踪分项变化，并与 loss 曲线对照；关键是固定探针集与版本。
