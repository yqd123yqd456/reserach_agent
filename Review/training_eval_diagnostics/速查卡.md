# training_eval_diagnostics 速查卡：拿到题后怎样开工

> 配套：[Knowledge/training_eval_diagnostics](../../Knowledge/training_eval_diagnostics/README.md)、[Practice/training_eval_diagnostics](../../Practice/training_eval_diagnostics/README.md)。

## 开工顺序

1. **建关联表**：每条评估记录能对上哪个 run、哪个 checkpoint、哪个任务、哪个版本的 suite 与 grader？对不上的先列出来。
2. **可比性检查**：任务集、suite 版本、grader 版本、评估配置、无效试验的数量与分布。不可比的点先标出，不参与比较。
3. **看曲线**，只描述、不解释：每个指标首尾各是多少。loss、BPB、reward 与通过率用**同一个 checkpoint 窗口**；有 checkpoint 因不可比被排除时，窗口随之缩短。
4. **配对比较 + 区间**（任务为单位），然后**分切片**。
5. **下钻到样本**：变化最大的任务 → 翻转的试验 → 读输出。每任务只有几次试验时，单个任务的下降分辨不了（k=3 时最极端的 3/3 → 0/3，单侧 p 也只有 0.05），这个列表只用来挑样本。
6. 有 reward 时做“reward 通过 × 独立通过”的四格分解。
7. 写结论：观察到什么（带区间）、哪些是噪声水平、竞争解释、每个解释需要的干预。

## 必须能回答的问题

- 这两个数能比吗？凭什么？
- 这个差异有多大的不确定性？统计单位是什么？
- 总分变化在各切片上方向一致吗？
- 你读过具体的输出吗？它们支持你的解释吗？
- 你的解释是观察还是因果？要变成因果需要做什么实验？
- loss 或 BPB 降了，任务分没变，你怎么解释？至少给三种可能和各自的验证方法。

## 常见错误

- 跳过可比性检查，把 grader 或任务集的变化当成模型的变化。
- 把无效试验当失败，或直接丢掉而不看它们集中在哪。
- 只看总分。
- 在每个切片上都找“显著”的变化，不考虑多重比较。草图的零假设模拟（合成数据，4 个切片各 10 个任务，2000 个种子）：没有真实变化时约 27% 的 run 至少有一个切片被标记；Bonferroni 区间下仍约 15%。
- 某个任务或整个切片在一侧没有有效试验，却不加说明地继续比较。
- 没读样本就给出机制解释。
- 把相关写成因果。

## 自测（闭卷）

1. BPB 怎样从逐 token 的交叉熵算出来？为什么按字节归一化？
2. verl 里 checkpoint 和验证指标靠什么关联？这有什么风险？
3. 要判断两次 Inspect 评估是否可比，至少核对哪五样？
4. 情境 B 中，怎样用一张四格表说明 reward 的上升不代表能力提升？
5. 发现某个切片退步后，为什么要在新任务上复核？

<details><summary>参考要点</summary>

1. 累加非特殊 token 位置的交叉熵（nat），除以 ln 2 与这些 token 的总字节数。按字节归一化使不同分词器的模型可比。
2. 只靠全局步数；checkpoint 目录里没有评估记录。若评估配置或 grader 之后变了，从 checkpoint 无法知道当时是用什么评的。
3. 任务与任务版本、数据集的样本 id、模型与生成配置、评估配置（样本上限、重复次数、限制）、代码版本与是否有未提交改动；还有评分器与完成样本数。
4. 按“reward 通过 × 独立通过”分格；上升的部分全部落在“只有 reward 通过”一格。
5. 多个切片各检验一次会抬高至少一个假阳性的概率；同一批任务既用来发现又用来确认，会高估效应。
