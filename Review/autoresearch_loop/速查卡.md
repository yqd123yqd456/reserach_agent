# autoresearch_loop 速查卡：拿到题后怎样开工

> 配套：[Knowledge/autoresearch_loop](../../Knowledge/autoresearch_loop/README.md)、[Practice/autoresearch_loop](../../Practice/autoresearch_loop/README.md)。

## 开工顺序

1. **先读懂真实机制**（30–45 分钟），不预设它有什么功能。写下：
   - 谁在驱动循环：代码，还是提示词？
   - 哪些文件可改、哪些固定？这种固定是代码强制的，还是约定的？
   - 指标在哪里算、用什么数据、由谁执行？
   - 预算怎样计、谁能改计数逻辑？
   - 结果记在哪里、是否可追溯到代码版本？
   - 超时、OOM、NaN、中断各由谁处理？
2. **列出问题清单，只选一个范围明确的改动**。写下不做的部分与理由。
3. **先写“怎样证明它有用”**：反例（它应该拦住什么）、对照（没有它时会怎样）、验收。
4. 实现最小版本；能在 CPU 上测的逻辑全部在 CPU 上测。
5. README：读到的机制、改动、证据、局限、哪些没有运行。

## 必须能回答的问题

- 这个改进属于代码修复、效率改善、能力提升，还是指标投机？凭什么？
- 一次改动让指标好了 0.001，该保留吗？噪声有多大，你怎么知道？
- 指标是谁算的？被测代码能影响它吗？
- 崩溃的实验在结果里是什么样子？会不会被当成一个数？
- 被丢弃的实验还能找回来吗？
- 在同一个验证集上选了 100 次之后，最终的数字还可信吗？

## 常见错误

- 没读代码就假设有调度器、有重试、有独立评估。
- 一次改很多地方，无法归因。
- 用同一个被反复选择的验证集证明自己的改进。
- 把替身或小规模实验的结果写成对真实系统的结论。
- 失败记为 0 或空值，混进统计。

## 自测（闭卷）

1. autoresearch 的“循环”由什么实现？仓库里有没有调用 LLM 的代码？
2. `val_bpb` 的评估条件里，哪三样在 agent 可改的文件中？
3. 固定 5 分钟墙钟预算带来什么好处，又让哪两类“改进”无法区分？
4. 崩溃在 `results.tsv` 里记成什么？有什么隐患？
5. 草图的保留规则比“只要更低就保留”多了哪三条？各自防什么？

<details><summary>参考要点</summary>

1. `program.md` 里的自然语言指令，由通用编码 agent 执行；仓库里没有 LLM 调用或编排代码。
2. 评估时的 batch 大小、算 loss 的前向函数、训练时间的计数与停止条件。
3. 好处：不同改动在同一平台上可直接比较。无法区分的是效率改善（同样时间内训练更多步）与能力提升。
4. `0.000000`，数值上是最好的值；不按状态过滤就取最小值会出错。
5. 噪声阈值（防靠波动“变好”）、显存上限（防用资源换指标）、受保护文件哈希（防评估条件被改）。
</details>
