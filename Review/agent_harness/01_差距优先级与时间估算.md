## 2. 学习时间估算（按模块）

假设：熟练 Python；每天可用时间未知；阅读指“读懂并能复述”，不是“能独立推导”；编码允许 AI 生成样板，判分与安全逻辑自己写。

| 模块 | 最短 | 标准 | 深入 | 最短版做什么 |
|---|---|---|---|---|
| Knowledge/06 公平比较 | 1h | 2h | 4h（读 Miller 原文 §2–5） | 读本页 + 手算一个配对 SE |
| Knowledge/05 + 04 | 2h | 4h | 8h（读 ABC 全文、τ² 评估代码） | 读两页 + 口述诊断五步 |
| Knowledge/01 + 02 | 1.5h | 3h | 6h（读 Inspect、τ² 评估代码） | 读两页 + 画出对象表 |
| Knowledge/07 | 2h | 4h | 8h（读 DAPO、verl `core_algos.py`） | 手算 G=4 例子 + DAPO 表 |
| Knowledge/08 | 1h | 2h | 5h（读 RE-Bench、PaperBench） | 读本页 + 准备 BPB 追问 |
| Knowledge/09 | 1.5h | 3h | 8h（精读 Khan、Kenton、Wen） | 读本页 + 写出 P1 的证伪条件 |
| Knowledge/03 | 0.5h | 1.5h | 3h | 读分母表 |
| Practice L1 | 4h | 8h | 12h | — |
| Practice L2 | 3h | 6h | 10h | 需要 API 凭据与预算 |
| Practice L3 | 8h | 16h | 24h | — |
| 一个岗位分支 | 4h | 8h | 24h | 见各分支 |
| 口述与自测 | 2h | 4h | 8h | 每岗位 30 秒 + 90 秒各录一遍 |

**合计**：只读 Knowledge 的最短路线约 10h；“标准阅读 + L1–L2 + 口述”约 40h；“深入 + L3 + 一个分支”约 100h 以上。

## 3. 时间不够时先砍什么

1. 先砍：Practice L3 的第二个环境、所有分支实验、深入阅读原文。
2. 保留：06、05、04 的标准阅读；Practice L1（它是“讲一条真实 run”的素材）；每个岗位的 30 秒与 90 秒口述。
3. Resolution 第一轮只需 09 的最短版 + 口述；后续轮次再加深。
4. Mirendil take-home 收到题目后，按题目重排：take-home 本身优先于其他一切阅读。

## 4. 完成状态的记录方式

对每个模块只记录实际发生的状态：未开始／已读／在提示下讲出／独立讲出／用新题验证过。不要因为文件写好了就标“已掌握”。
