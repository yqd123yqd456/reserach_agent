# grading 速查卡：拿到题后怎样开工

> 配套：[Knowledge/grading](../../Knowledge/grading/README.md)、[Practice/grading](../../Practice/grading/README.md)。

## 开工顺序（前 30 分钟）

1. **读标准，拆成可逐条判定的检查项**。每一项问：能用代码确定吗？需要可信证据（日志、状态）吗？只能靠判断吗？
2. **看 5–10 个真实输出**再写规则。先找出格式上的等价形式和常见的不规范写法。
3. **定三层规则并写下来**：单项的四种状态（pass／fail／unknown／error）；样本成功的定义；聚合口径（unknown 怎么算、缺失输出怎么算）。
4. **先写样例再写代码**：正确、局部错误、等价正确、欺骗性、解析失败、缺失输出，各带逐项期望标签。
5. 写确定性检查 → 跑 audit → 再处理 judge 部分。
6. README 里写清：判分规则、两种口径的数字、已知局限、哪些部分没有运行。

## 必须能回答的问题

- 这个检查在什么输入上会误接受？什么输入上会误拒绝？各给一个例子。
- 空输出、解析失败、judge 不确定，分别计为多少分？为什么？
- 同一批输出，strict 与 loose、样本级与检查项级的数字差多少？
- judge 看到的证据从哪里来？提交里写给 grader 的话会不会影响它？
- 规则改了以后，旧样本的分数怎么办？（版本号 + 重判）

## 常见错误

- 用 judge 判断本可以对照日志确定的事。
- 把 unknown 当通过，或把解析失败的样本从分母里去掉。
- 只报一个总分，不报各检查项的分布与待复核数。
- 期望标签是看了 grader 输出后才写的。
- 归一化不足（大小写、百分号、顺序）造成大量误拒。

## 自测（闭卷）

1. IFEval 的 loose 模式做了哪些变换？它减少了哪类错误，增加了哪类错误？
2. prompt 级准确率与 instruction 级准确率的分母各是什么？
3. Inspect 的 `model_graded_qa` 解析不到分数时怎么处理？PaperBench 的 judge 呢？各有什么后果？
4. 为什么“报告的每个数字都能在日志中找到”不足以防止欺骗性报告？
5. 成对比较的 judge 怎样缓解位置偏差？

<details><summary>参考要点</summary>

1. 去掉首行、末行、两者，以及去掉 `*`，共 8 个变体，任一通过即通过。减少误拒，增加误收（原文举了字数约束的例子）。
2. prompt 级：prompt 总数（全部指令满足才算）；instruction 级：指令总数（微平均）。
3. Inspect：未评分，不判错；PaperBench：该叶子 0 分并标记无效，但聚合时不区分。后者会让“judge 出错”和“提交不满足”混在一起。
4. 可以只报告最好的 run（挑选），或基于正确数字做不成立的结论（夸大）。需要完整性检查和结论与数据方向的检查。
5. 两种顺序各判一次，只有两次都偏向同一答案才算赢，否则算平。
