# Mirendil take-home 执行指南：怎样用这些材料交付

> 写于 2026-11-14。这是横跨六个专题的**执行**指南，不新增知识内容。
> **前提**：题目、时限、语言、AI 使用规则都未知。下面的 12 小时是我们的准备情境。拿到正式题目后，时限与 AI 规则以题目为准；规则不允许的做法（例如由 AI 实现）一律不用，本指南相应部分作废。
> 专题入口见 [Companies/Mirendil.md §5](../../Companies/Mirendil.md#5-take-home-准备六个专题)。

## 0. 三条总原则

1. **只做一条端到端路径，再加验证**。六个专题是地图，不是清单。交付一个窄而完整、每个结论都有证据的东西，好过六个半成品。
2. **“运行通过”不等于“正确”**。本仓库的草图就出过这样的问题：一个检查脚本只打印结果、不做断言；一个比较逻辑靠匹配错误文字，漏掉了一种错误；一个测试把已终止的僵尸进程当成存活。完成的证据是：**一条命令、它的实际输出、以及一个“改坏后会失败”的反向验证**。
3. **你必须能解释每个关键设计**。代码可以由 Claude 写，判断由你负责：选什么切口、判分规则是什么、哪些情况算失败、局限是什么。

## 1. 拿到题后怎样选切口

### 1.1 前 30 分钟：读题并回答五个问题

| 问题 | 写下来的答案 |
|---|---|
| 题目要支持什么**决策**？ | 例如“这个 checkpoint 能不能发布”“这个 agent 失败在哪” |
| 给了什么**输入**？ | 日志、模型输出、任务、代码仓库、还是只有一句描述 |
| 要交什么**产物**？ | 脚本、工具、报告、任务集；有没有明确的验收 |
| **规则**是什么？ | 时限、语言、允许的模型与预算、AI 工具是否允许、是否要真实模型运行 |
| 什么算**最低可交付**？ | 一句话：输入 X，运行一条命令，得到 Y，并且有 Z 证明它是对的 |

规则没写清楚的地方，先问出题方。问不到就在 README 里写明你的假设。

### 1.2 从题目信号映射到专题

| 题目里出现 | 主专题 | 多半还要用到 | 最低验收 |
|---|---|---|---|
| “判分”“rubric”“评估这些输出”“写一个 scorer／judge” | [grading](../../Knowledge/grading/README.md) | agent_harness 05 | 逐项结果带证据；缺失与解析失败有固定规则；6 类样例的 audit 通过 |
| “设计任务／benchmark”“衡量某种能力” | [task_dataset_design](../../Knowledge/task_dataset_design/README.md) | grading | 一个完整任务：oracle 通过、no-op 失败、两个合法解通过、三条捷径被拒 |
| “给了一堆日志／trace，做个工具帮人看” | [trace_viewer](../../Knowledge/trace_viewer/README.md) | agent_harness 01a | 按用户 journey 的 5 步都能走通，并有带断言的检查 |
| “训练日志”“多个 checkpoint”“回归检测”“指标变化” | [training_eval_diagnostics](../../Knowledge/training_eval_diagnostics/README.md) | agent_harness 06 | 可比性检查 + 配对差与区间 + 分切片 + 至少一次下钻到样本 |
| “很多 rollout，找出失败原因”“用 agent 分析” | [agent_failure_investigation](../../Knowledge/agent_failure_investigation/README.md) | agent_harness 04、trace_viewer | 每条结论带可校验的引用；有预置故障与对照的评估 |
| “改进这个实验循环／研究 agent” | [autoresearch_loop](../../Knowledge/autoresearch_loop/README.md) | training_eval_diagnostics | 先写清真实机制；一个范围明确的改动 + 反例 + 对照 |
| “搭一个 eval harness／跑一个 agent 并评估” | [agent_harness](../../Knowledge/agent_harness/README.md) | grading、task_dataset_design | 一条 run 落盘、可重判；一成功两失败样例 |

题目常常跨两三个专题。**只选一个作主线**，其余的只做到主线需要的程度。例如题目是“评估一个研究 agent”：主线是 task_dataset_design（一个任务做到底），grading 只做该任务的 verifier，trace 只落盘、不做界面。

### 1.3 定下范围：写三张小表

1. **做**：最低可交付（一条路径）+ 两个加分项（按价值排序）。
2. **不做**：列出来并写一句理由。它会原样进 README。
3. **验收**：最低可交付的 3–5 条可执行检查。

每个专题的 `Review/<专题>/速查卡.md` 开头有该题型的开工顺序，这时只读对应的那一张。

## 2. Claude 和你怎样配合

以下假设规则允许 AI 实现。**如果规则限制 AI，按规则调整分工**；本仓库的分工建议不能凌驾于题目规则之上。

### 2.1 分工

| 环节 | 你 | Claude |
|---|---|---|
| 读题、选切口、定范围 | **决定**；写下 §1.3 的三张表 | 提出选项与取舍；指出题目里的歧义 |
| 数据合同（schema、文件布局） | 审核并批准；能说出每个字段为什么存在 | 起草；用一个真实样例展示 |
| 判分规则、policy、验收标准 | **决定**规则本身；写出期望标签 | 实现；构造反例；报告规则没覆盖的情况 |
| 实现、运行、调试 | 看输出；抽查关键代码 | 写代码、跑、修；每步给出命令与实际输出 |
| 验证 | 指定要验证什么；读反向验证的结果 | 写断言、反例、反向验证；不通过就修，不改测试来迁就 |
| README 与演示 | 自己写或逐句确认；演示由你讲 | 起草结构；核对每个数字都能对上一条命令 |

### 2.2 每个阶段的固定回路

```text
1. 你：说明这一步的目标与验收（一两句）
2. Claude：先用三五句话讲设计 —— 输入输出、关键选择、会怎样失败
3. 你：确认或修改设计                      ← 不理解就在这里问，不要等到代码写完
4. Claude：实现并运行；贴出命令与实际输出
5. Claude：做一个反向验证（故意改坏、或给一个应当失败的输入），贴出结果
6. 你：复述这一步做了什么、为什么对；复述不出来就让 Claude 再讲，或缩小这一步
7. 记一行进度：做了什么、证据在哪、还欠什么
```

第 6 步是这套配合的核心：**每个阶段结束时，你能用自己的话讲清它**。最后的演示就是把这些复述串起来。

### 2.3 可以直接用的提示

开工：

```text
这是题目全文和规则：<粘贴>。先不要写代码。请：1) 用五句话复述题目要支持的决策、输入、产物；2) 列出题目里不明确的地方；
3) 对照 Review/mirendil_takehome/执行指南.md §1.2 提出一个主专题和最低可交付；4) 列出你建议不做的部分。等我确认后再继续。
```

每个阶段：

```text
目标：<一句话>。验收：<可执行的检查>。先讲设计（输入输出、关键选择、失败方式），等我确认再实现。
实现后给我：运行命令、实际输出、一个反向验证的结果。不要只说“已完成”。
```

要求解释：

```text
用我能在面试里复述的方式解释 <模块>：它读什么、写什么、最容易错在哪、我们怎样确认它没错。配一个具体的输入输出例子。
```

收尾：

```text
对照 README 里的每个数字和每句“已验证”，逐条给出产生它的命令。对不上的标出来。再列出所有没有运行过的部分。
```

### 2.4 你不能外包的四件事

1. 选切口与砍范围。
2. 判分规则与“什么算失败”的定义。
3. 判断一个结果是否可信（看过样本没有？有没有对照？）。
4. 对局限的陈述。

## 3. 准备不足时怎样开始

不需要先读完知识库。按下面的顺序，**读一页、做一步、看到输出**，再读下一页。

| 步 | 读（最少） | 做（可验证的一小步） | 看到什么算完成 |
|---|---|---|---|
| 1 | [agent_harness 01a](../../Knowledge/agent_harness/01a_execution_harness一次run的完整过程.md) 的 §1–§4 | 运行 `Practice/agent_harness/sketch/minimal_run.py`，打开生成的 `events.json` 与 `verdict.json` | 能指着文件说出：哪一步调用了什么、哪个检查为什么失败 |
| 2 | 题目对应专题的**速查卡**（一页） | 让 Claude 对题目给的数据跑一个“只读不写”的探查脚本：有多少条、有哪些字段、缺什么 | 一张数据概况表 |
| 3 | 该专题主文的“贯穿例子”一节 | 把最低可交付缩成一个样本：一个输入走完全程，输出一个结果 | 一条命令，一行正确的输出 |
| 4 | 该专题主文的“验收”或 audit 一节 | 加第一个反例：一个应当失败的输入 | 它确实失败，且失败原因写在输出里 |

之后才扩展到全部数据。遇到不懂的概念，问 Claude “用一个具体例子解释，并指给我仓库里对应的一节”，而不是回去通读。

**背景最少要知道的五件事**（每件一句话，细节在链接里）：
- 模型只提议调用，校验、拦截、执行、计数都在 harness 里（[01a](../../Knowledge/agent_harness/01a_execution_harness一次run的完整过程.md)）。
- 判分读落盘的状态与日志，不读被测对象的自述（[Practice 00 §2](../../Practice/agent_harness/00_共用harness规格.md#2-数据合同l1-起就固定)）。
- 判不了（unknown）与出错（error）不是通过，也不能从分母里消失（[grading §5](../../Knowledge/grading/README.md#5-strictloose部分得分与各种判不了)）。
- 比较要在同一批任务上配对，统计单位是任务（[06](../../Knowledge/agent_harness/06_公平比较与统计.md)）。
- 验证器本身要被验证：正例、反例、什么都不做（[05](../../Knowledge/agent_harness/05_verifier的验证与防作弊.md)）。

## 4. 12 小时怎样分配（准备情境）

假设：允许 AI 实现；有一台能跑 Python 的机器；题目规模与本仓库的草图相当。时限不同时按比例缩放，**各阶段的顺序与退出条件不变**。

| 阶段 | 时间 | 做什么 | 退出条件（没达到就不进入下一阶段） |
|---|---|---|---|
| 1 理解题目 | 0:00–1:00 | §1.1 五个问题；探查数据；定范围三张表 | 最低可交付写成了一句话；“不做”列表有了 |
| 2 第一条端到端路径 | 1:00–4:00 | 一个样本从输入走到结果；数据合同定下来；一条命令可运行 | 命令在干净目录里能跑；输出与手工预期一致 |
| 3 扩到全部输入 + 失败处理 | 4:00–6:30 | 全量数据；缺失、解析失败、无效输入各有固定规则；不崩溃 | 每种异常输入至少一个样例，行为符合写下的规则 |
| 4 验证 | 6:30–8:30 | 断言化的检查；反例；至少一个反向验证；（判分类）audit；（比较类）区间 | 检查脚本失败时以非零状态退出；反向验证确实失败 |
| 5 一个加分项 | 8:30–10:00 | 范围表里排第一的那个 | 同样有命令、输出、检查 |
| 6 README | 10:00–11:00 | 怎样运行；设计与规则；结果；局限；没有运行的部分 | 每个数字都能对上一条命令 |
| 7 演示准备与缓冲 | 11:00–12:00 | 按 §5 讲一遍并计时；从干净目录重跑一次全部命令 | 讲得下来；重跑通过 |

**进度落后时砍什么**（按顺序砍，砍到追上为止）：

1. 阶段 5 的加分项，整个砍掉。
2. 界面、图表、美化：改成文本表格输出。
3. 第二种数据格式或第二个环境的支持。
4. LLM judge 或真实模型调用：改成确定性检查加“此处需要 judge，未实现”的说明。
5. 阶段 3 的覆盖面：只保留最常见的两种异常输入，其余列进局限。

**不能砍的**：一条端到端路径；至少一个反例与一个反向验证；README 里的局限与“未运行”清单。到 4:00 还没有端到端路径时，立刻缩小最低可交付，而不是加班赶原计划。

每小时花两分钟记一行进度（完成了什么、证据、下一步），防止后半程不知道时间花在哪。

## 5. 最后怎样讲清楚

演示按下面五段准备，总共 6–8 分钟。每段都要有一个能指着看的东西（文件、输出、图）。

| 段 | 讲什么 | 指着什么 | 你要能回答的追问 |
|---|---|---|---|
| 1 问题与范围（1 分钟） | 这个交付支持什么决策；做了什么、没做什么、为什么 | README 的范围一节 | 为什么选这个切口？如果再有一天，先做什么？ |
| 2 数据流（1.5 分钟） | 一个输入从进来到出结果，经过哪些模块，每个模块读什么写什么 | 一张 5 行以内的流程，或直接指落盘文件 | 这个字段为什么需要？这一步出错时会发生什么？ |
| 3 规则与判定（1.5 分钟） | policy／verifier／grader 的规则；判不了与出错怎么算；它们由谁、在何时执行 | 一条 CheckResult 及其证据 | 什么输入会被误接受？什么会被误拒？你怎么知道规则本身是对的？ |
| 4 一次失败及修复（1.5 分钟） | 开发中真实遇到的一个错误：现象、怎样发现、原因、修复、现在由哪个检查守着 | 修复前后的输出，或那个反向验证 | 还有哪些类似的错误可能没被发现？ |
| 5 局限与下一步（1 分钟） | 没验证的部分；结论的适用范围；最值得做的下一步 | README 的局限一节 | 哪个结论你最没把握？ |

第 4 段最能说明问题。本仓库就有现成的素材，演示时用你自己项目里的同类经历：
- 训练 bug 任务：症状描述与实际运行不符；第一版可见检查让什么都没改的代码通过（[task_dataset_design §3](../../Knowledge/task_dataset_design/README.md#3-贯穿例子一个训练-bug-任务)）。
- 权限规则：只检查“验证过”，没检查“验证的是谁”，多客户场景下误接受（[Practice 00 §3.3](../../Practice/agent_harness/00_共用harness规格.md#33-policy-与-verifier写操作必须绑定到具体客户)）。
- 检查脚本只打印不断言；比较逻辑靠匹配文字；测试把僵尸进程当存活（本指南 §6）。

**讲之前自查**：不看稿，把五段各用两句话说一遍。哪一段说不出来，就回到对应的代码与输出，让 Claude 再解释一次，直到你能复述。

## 6. 完成的证据标准

对每一句“已完成”“已验证”，要能给出三样东西：

| 证据 | 例子（来自本仓库） |
|---|---|
| 一条命令 | `node check_viewer.js` |
| 它的实际输出 | `CHECK PASSED: 13 assertions` |
| 一个反向验证：把被测对象改坏，检查应当失败 | 把“失败”筛选条件改反后，同一脚本以非零状态退出 |

2026-11-14 对本仓库草图的复核与修正（都按上面的标准重新验证过）：

| 位置 | 原问题 | 修正 | 验证 |
|---|---|---|---|
| [`diagnose.py`](../../Practice/training_eval_diagnostics/sketch/diagnose.py) | 任务集合变化时返回的文字是 “task sets differ”，而阻止比较的逻辑只匹配 “differs”，于是会不加说明地在交集上继续比较 | 可比性问题改为结构化的类型与 `blocking` 字段；版本不同 → 停止比较；任务集合不同 → 只在共同任务上比较并写明，共同任务不足 80% 时停止；没有共同任务时不再除以零 | `python3 diagnose.py --selftest`，7 条断言 |
| [`check_viewer.js`](../../Practice/trace_viewer/sketch/check_viewer.js) | 只收集并打印结果，没有断言 | 加预期值；任一不符或出现页面脚本异常时以非零状态退出 | 正常页面 13 条断言通过；故意改坏筛选逻辑后退出码为 1 |
| [`run_experiment.py`](../../Practice/autoresearch_loop/sketch/run_experiment.py) | 超时处理只有 POSIX 的进程组终止，原生 Windows 不支持 | 按平台分支：POSIX 杀进程组；Windows 用 `taskkill /T /F` 终止进程树 | POSIX：[`test_kill_tree.py`](../../Practice/autoresearch_loop/sketch/test_kill_tree.py) 确认孙进程被终止，且只杀直接子进程时测试失败。**Windows 分支未实测** |

其余复核结果见各专题 Practice 的“已知问题与修正”一节。

## 7. 一页清单（开工时放在手边）

- [ ] 规则读清了：时限、语言、AI 是否允许、是否要真实模型运行
- [ ] 最低可交付写成了一句话；“不做”列表有了
- [ ] 只选了一个主专题
- [ ] 第一条端到端路径在 4 小时内（按比例）跑通
- [ ] 缺失、解析失败、无效输入各有固定规则
- [ ] 检查会失败（非零退出），并且做过反向验证
- [ ] 结果带统计单位与不确定度（如果有比较）
- [ ] 至少一次从数字下钻到具体样本
- [ ] README：运行方式、规则、结果、局限、未运行的部分；每个数字对得上命令
- [ ] 从干净目录重跑过全部命令
- [ ] 五段演示能不看稿讲下来
