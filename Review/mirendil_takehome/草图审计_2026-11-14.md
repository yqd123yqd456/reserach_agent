## 怀疑但未确认为缺陷

- `verifier.py`：返回硬编码权重的 `train` 能通过全部隐藏检查（审查者已运行确认）。Practice 的练习 2 预见了这一点，但“隐藏 verifier 误接受 0”只对审计脚本里的 7 个候选成立。
- `diagnose.py` 的切片标记：在没有真实变化的模拟下，每个切片约 9.8% 被误标，约 34% 的 run 至少有一个标记。练习 4 覆盖了这一点。
- `diagnose.py`：run A 的 loss／BPB 报告的是 1000→4000，通过率比较的是 1000→3000，窗口不一致。
- `diagnose.py` 的“最大的任务级下降”总是打印三个任务，即使全是噪声。
- `minimal_run.py`：注入 503 的 run 的 `valid` 也写死为 True；`diff()` 把 `None` 与缺失的键视为相等（`normalize.py` 同）。
- `grade_report.py`：0.941 与 0.946 在容差 0.005 下因浮点误差判为不符；strict 模式接受多余的章节。
- `viewer.html`：搜索会匹配 JSON 的键名（搜 “flags” 命中所有 run），但不搜检查项名称。
- `run_experiment.py`：可执行文件不存在时抛 `FileNotFoundError`、没有记录。

## 检查后认为没有问题的

- `minimal_run`：被执行的调用不会超过预算；每个 call id 恰好一个结果；没有最终回复的脚本以预算耗尽结束。
- `grade_report`：`"94.1 %"`、`1e-1`、`.941` 作为单元格、对齐行、多余的列都能解析。
- `viewer`：正则元字符已转义；未发现 XSS；筛选为空与自己对比自己时不报错。
- `diagnose`：bootstrap 下标至多差一位；没有有效试验的任务被丢弃而不是记 0。
- `gen_synthetic`：三个情境与说明一致。
- `score_assistant`：`compatible()` 符合意图；对照组被标为误报。
- `run_experiment`：无结尾换行没问题；超时返回码为 −9 且进程组被杀；增益恰等于阈值时保留；失败的记录不带指标。
