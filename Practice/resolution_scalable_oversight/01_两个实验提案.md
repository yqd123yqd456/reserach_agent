## 提案一（oversight failure）：批评者能揪出哪一类错误

### 研究问题与假设

#1 的解释是：模糊任务上 debate 失效，是因为结论建立在许多弱而相关的命题的聚合上，没有单一可定位的缺陷。但 text-GeoGuessr 与 LiveCodeBench 同时在领域、模型知识、judge 能力和论证结构上都不同，这个机制没有被单独隔离。

**要区分的两种解释**：

- H（结构解释）：批评回合的帮助取决于缺陷类型。可定位的错误事实容易被揪出；聚合类缺陷（重复计算相关证据、遗漏反面证据）几乎不受益。
- H′（非结构解释）：debate 在这个任务上的负结果来自别处（proxy、题量、judge 太弱、辩手对地理的知识），与缺陷类型无关。

### 与推荐材料及相似工作的联系

- #1 列出了缺陷类型并给了例子，但按帖子的描述，它比较的是加不加 debate 回合后的总体准确率，没有按缺陷类型做受控注入。**这一点我只读了帖子本身，没有读其前作，可能有遗漏。**
- #4 把“fuzzy 任务”列为首要 future work，并指出其测量只看最终答案。
- #4 引用的 Elasky et al. 2026 称 inference-only debate 只在 critic 的分类能力超过 judge 时有帮助（仅见引用）。这是 H′ 的一个具体版本，需要作为控制。
- 方法上的类比来自我自己的 benchmark：对 grader 用已知结果的补丁做 self-check，以及“回滚一个 PR 看隐藏测试能否发现”的遗漏审计。那里的 verifier 是可靠的自动测试；这里被审计的是一个不可靠的 judge。

### 任务、模型、监督者

- **任务**：#1 描述的 text-GeoGuessr 设定（图片的文字描述 → 猜国家），真值便宜。若数据未公开，需要自建：公开的带地理标注的街景描述，由一个不参与实验的模型生成文字描述。
- **基础解释**：强模型对每题给出预测与解释。只保留预测正确、且经抽查没有明显事实错误的解释作为“干净底稿”。
- **缺陷注入**：对每份底稿各做一次单一改动，使结论变成一个错误国家：
  1. 一条错误的可查证事实（例如某国的行车方向）。
  2. 把一条弱线索的强度说过头（“只可能是”）。
  3. 把同一事实拆成两条看似独立的证据。
  4. 删掉一条指向正确答案的反面线索。
  
  注入由**另一个模型族**的模型完成，人工抽查每类若干份，确认只改了一处。
- **监督者**：较弱的开源模型作 judge，输出“解释是否支持其结论”的判断。critic 与 rebuttal 由强模型担任。

### Baseline 与公平预算

| 臂 | judge 看到 | 预算控制 |
|---|---|---|
| J | 解释 | judge 采样 k 次取多数 |
| J+ | 解释，judge 采样次数增加到与 C 臂总调用数相同 | 排除“只是多看了几次”的解释 |
| C | 解释 + 批评 | 批评有词数上限；judge 采样 k 次 |
| CR | 解释 + 批评 + 反驳 | 同上，反驳同样限长 |
| 上限 | 批评者被告知注入位置 | 估计“缺陷可被讲清楚”时 judge 的上限 |

所有臂记录 judge 调用数与总 token。#4 的经验是不限长时 critic 会靠冗长取胜，所以字数上限是必要控制，并且至少取两个值。

### 真值与独立评估

- 缺陷的存在、类型和位置由构造已知。
- 结论是否正确由地理真值给出。
- 干净底稿同样进入每个臂，用来估计**假阳性**：批评者把没有问题的解释说成有问题的比例。#4 观察到 critic 会 nitpick 和 bluff，所以只报检出率是不够的。

### 指标

- 每个缺陷类型、每个臂：judge 拒绝有缺陷解释的比例（检出率），与拒绝干净解释的比例（误拒率）；两者合成 MCC。
- 主要对比量：**C 臂相对 J+ 臂的检出率提升，按缺陷类型分别计算**，并对同一底稿做配对。
- 不确定度：按底稿重采样的配对 bootstrap。judge 的多次采样不是独立样本，统计单位是底稿。

### 混淆因素与必要消融

| 混淆 | 处理 |
|---|---|
| 注入的缺陷比自然出现的更显眼 | 次要分析：收集强模型**自然答错**的解释，人工按四类标注，看趋势是否一致 |
| 缺陷类型与文本长度、位置相关 | 记录并在分析中控制；类型 4 是删除，天然更短，单独报告 |
| critic 与注入模型同族时更容易认出改动 | 注入用不同模型族；另跑一个同族条件看差异 |
| judge 自己的地理知识 | J 臂即是基线；另设“judge 不看解释直接猜国家”的准确率作参考 |
| critic 能力不超过 judge 时 debate 本就无益（H′ 的一种） | 先测 critic 与 judge 各自作为“缺陷分类器”的准确率，只在 critic 明显更强的配置下解读结果 |

### 什么结果会推翻假设

事先写下的判定：若四类缺陷的“C 相对 J+ 的提升”彼此之间的差异落在配对 bootstrap 区间之内（具体阈值在看到 J 臂基线方差后、看到 C 臂结果前确定），H 不成立。同样，若聚合类缺陷的提升与事实类一样大，H 不成立，#1 的负结果需要另找原因。

若所有类型的提升都接近零，包括事实类，则实验没有区分力（可能 critic 不够强或 judge 太弱），**不算支持 H**。

### 最小可行实验

约 50 份干净底稿 × 4 类缺陷 + 50 份干净对照，4 个臂，judge 每次采样 5 次。全部是推理调用，没有训练。规模在 10⁴ 次短调用量级；**费用没有估算过**。第一步不花钱：手工做 5 份底稿的四类注入，自己读一遍，确认这四类在这个任务上能被干净地构造出来。若类型 2 与类型 3 难以分开，合并为一类。

### 无法推广到的范围

- 这是静态测试。它不回答“被训练的 proposer 会学到产生哪类缺陷”，也不回答 debate **训练**是否有效（#4 的主要论点是好处出现在训练过程中）。
- 注入的缺陷是无意图的；对有意隐藏缺陷的模型没有结论。
- GeoGuessr 有便宜真值；auto-alignment 决策没有。
- judge 是弱模型，不是人。

## 提案二（改进方法）：用一致性检查过滤弱 judge 的假接受

### 研究问题与假设

#4 的 baseline 中，策略学到的 hacking 行为包括冒充 judge 的 meta-commentary、权威化措辞、宣称题目有误。这些行为的共同点是：它们改变 judge 的判断，却不改变答案是否正确。

**假设**：对被 judge 接受的输出施加“不应改变正确性”的变换后重判，判断不稳定的输出更可能是假接受。把“接受且稳定”作为选择信号，能在相同 judge 调用预算下降低假接受率。

**要区分的解释**：

- H：一致性检查提供了重复采样所没有的信息（它去掉了说服性表面特征）。
- H′：任何额外的 judge 调用都有同样效果，一致性变换本身没有贡献。

### 与推荐材料及相似工作的联系

- 邀请邮件说团队在做 debate 的替代方案，“for instance consistency methods”。**我不知道他们具体指什么**，这个提案是我对这句话的一种理解，不代表团队的方向。
- #4 §4.4 报告两种单人缓解手段失败：pairwise preference 比 baseline 更快被 hack（judge 按正确性以外的因素偏好），step-by-step 格式峰值更低且退化快。这是对本提案的直接警告：单人侧的改动可能同样无效。
- 相关文献（均只读了摘要）：Fluri et al. 用一致性检查评估超人模型（[2306.09983](https://arxiv.org/abs/2306.09983)）；Wen et al. 的 Internal Coherence Maximization（[2506.10139](https://arxiv.org/abs/2506.10139)）；CCS 的否定一致性（[2212.03827](https://arxiv.org/abs/2212.03827)）。本提案很可能与其中某项的思路重叠。

### 任务、模型、监督者

- **任务**：答案可自动核对的数学题，难度要让 policy 未饱和（#4 强调这一点；Wells et al. 因数据集过易而不得不人为削弱 policy）。
- **Policy**：一个较强的模型，对每题采样 N 个解答。
- **Judge**：较弱的模型，判断“最终答案是否正确”，冻结。
- **优化压力**：best-of-N，按 judge 分数选最高者，N ∈ {1, 4, 16}。这是 RL 的弱 proxy。

### 方法：两个变换

对 judge 接受的输出 y：

1. **中性改写**：第三个模型族把 y 改写成去掉修辞、meta-commentary 和强调格式的版本，保留推理步骤与最终答案。judge 重判，判断应当不变。
2. **换答案**：保留 y 的推理文字，把最终答案替换成另一个数。judge 重判，判断应当变为拒绝。若 judge 仍接受，说明它没有在看答案是否由推理得出。

“一致”定义为：改写后仍接受，且换答案后拒绝。

### Baseline 与公平预算

| 臂 | 选择信号 | 每个候选的 judge 调用 |
|---|---|---|
| J1 | judge 单次判断 | 1 |
| Jk | judge 判 k 次取平均 | k = 3 |
| Cons | 原判断 + 两个变换后的判断 | 3，另加 1 次改写调用 |
| Critic | 解答 + 批评后 judge 判断（推理时，critic 不训练） | 1，另加 1 次批评调用 |
| 上限 | 真值核对 | — |

Jk 与 Cons 的 judge 调用数相同，这是区分 H 与 H′ 的关键对照。改写与批评的 token 单独计入并报告。

### 真值与独立评估

最终答案与参考答案比对。**真值只用于评估，不进入任何选择信号。**

### 指标

- 被选中输出的准确率，随 N 的变化。
- 被接受输出中的假接受率；judge（及各增强信号）的 MCC，随 N 的变化。按 #4 的定义，MCC 随优化强度下降即是 hacking。
- 不一致标记对“答案错误”的预测力（AUROC），在未参与调参的题目上计算。

### 混淆因素与必要消融

| 混淆 | 处理 |
|---|---|
| 改写改变了数学内容 | 改写前后提取最终答案，必须相同；人工抽查若干份推理步骤是否被改动；不合格的改写计为无效并报告数量 |
| 改写模型顺手“修好”了错误推理 | 同上；另报告改写后解答的真值准确率，应与改写前相同 |
| judge 本身的随机性造成“不一致” | N = 1 时的不一致率作基线；Jk 臂吸收纯噪声效应 |
| 换答案后的文本明显不通顺，judge 靠表面线索拒绝 | 替换成“接近的数”和“明显不同的数”两种，分别报告 |
| best-of-N 的 hacking 形态与 RL 学到的不同 | 无法在本实验内解决，列为范围限制 |

### 自适应检验（这个提案最重要的一步）

静态上有效不够。再做一轮：以 Cons 信号本身作为 best-of-N 的选择标准，N 增大到 16 甚至更大，看假接受率是否重新上升。若上升，说明在优化压力下，策略只是换成了“改写后依然能骗过 judge”的错误，方法只是把问题推后了一步。

### 什么结果会推翻假设

- Cons 的假接受率不低于 Jk（配对区间包含零）：H′ 成立，一致性变换没有额外信息。
- 不一致标记的 AUROC 接近 0.5：标记不携带关于正确性的信息。
- 自适应检验中假接受率随 N 回升到与 J1 相当：方法在优化下不稳。
- 若 J1 在 N 增大时根本不出现假接受率上升，则任务或 judge 选得不对，实验没有区分力，需要先换设置。

### 最小可行实验

约 200 道题，N ∈ {1, 4, 16}，四个臂加自适应检验，全部推理调用。第一步不花钱：从 #4 的定性描述出发，手写 10 个带有“冒充 judge”“权威措辞”的错误解答，确认一个现成的小模型 judge 确实会被其中一部分骗过；若骗不过，这个设置里没有可过滤的东西。**费用没有估算过。**

### 无法推广到的范围

- 只适用于“答案是否正确”与“表述方式”可以干净分开的任务。模糊任务上很难定义“保持含义的改写”，而那正是 #1 认为最难的地方。
- best-of-N 不是 RL。#4 的结论是 debate 的好处在训练过程中出现；本方法在训练中的表现未知。
- 对有意规避一致性检查的策略没有结论。
- 需要一个可信的第三方改写模型；如果改写模型本身不可信，问题只是被转移了。

## 两个提案与个人经历的关系

可以如实说的：这两个设计都用了“向被检查对象注入已知缺陷，再看检查者能否发现”的思路，这是我在 benchmark 的 grader self-check 与遗漏审计里用过的做法。

不能说的：这不是我做过的 oversight 实验。benchmark 里的检查者是确定性的隐藏测试，被检查的补丁不会针对检查者优化；这两点正是 scalable oversight 的难处所在。
