# Practice：合成训练日志与诊断脚本

> 状态：[`sketch/gen_synthetic.py`](sketch/gen_synthetic.py)、[`sketch/diagnose.py`](sketch/diagnose.py) 与 [`sketch/test_diagnose.py`](sketch/test_diagnose.py) **已在本地运行**（2026-11-14，只用标准库；前两个几秒钟，`--null-sim 2000` 约 80 秒）。**数据是合成的教学数据**，效应由生成脚本设定，不来自任何真实训练。没有训练任何模型。
> 概念与逐情境的诊断过程见 [Knowledge/training_eval_diagnostics](../../Knowledge/training_eval_diagnostics/README.md)。

## 1. 运行

```bash
cd Practice/training_eval_diagnostics/sketch
```

```bash
python3 gen_synthetic.py
```

```bash
python3 diagnose.py
```

```bash
python3 diagnose.py --selftest
```

```bash
python3 test_diagnose.py
```

```bash
python3 diagnose.py --null-sim 2000
```

- `--selftest`：13 条函数级断言语句，覆盖可比性检查的各种情况（版本不同、任务集合少量或大量不同、无效试验、任务被剔除、切片整体缺失）、没有共同任务时的配对比较、Bonferroni 区间、Fisher 检验、缺字段的试验。
- `test_diagnose.py`：7 个场景级测试。每个测试在临时目录里写一份手写的小数据，把 `diagnose.py` 当作命令行程序运行并检查输出。可以把另一个脚本路径作为参数，用同一组测试去跑旧版本。任一失败时退出状态为 1。
- `--null-sim N`：在内存里重新生成 N 份没有真实变化的数据，打印切片被误标的比例；不写文件。结果与读法见 Knowledge §4 情境 C 末尾。

生成的 `data/` 下有 `runs.json`（run 与任务定义）、`train_log.jsonl`（每个 checkpoint 一行）、`eval_results.jsonl`（1,440 条试验记录）。

## 3. 离线练习（不需要训练模型，不需要 API）

| # | 练习 | 验收 | 估时 |
|---|---|---|---|
| 1 | **先不看生成脚本**，只看 `diagnose.py` 的输出，为每条 run 写三句话：什么变了、哪些变化可信、下一步验证什么。再对照生成脚本 | 三条 run 的结论与生成脚本的设定一致；能指出哪些切片波动是噪声 | 45 分钟 |
| 2 | 把 `K` 从 3 改成 1 重新生成并诊断 | 说明哪些结论还成立、哪些区间变宽到无法下结论 | 30 分钟 |
| 3 | 给 `diagnose.py` 加“重判”：用 `grader-v1` 的规则重新判 run A step 4000 的记录（提示：合成数据里没有存输出，所以需要先在生成脚本里为每条记录存一个潜在的“v1 判定”） | 说清为什么真实系统里必须保存输出才能重判 | 1 小时 |
| 4 | 先不运行，估计“任一切片的配对差区间上界小于 0 就报警”在没有真实变化时的误报率；再运行 `python3 diagnose.py --null-sim 2000` 对照。然后把 `gen_synthetic.py` 里每个切片的任务数从 10 改成 40、重新生成，再运行一次 | 解释误报率与“4 个切片各检验一次”的关系；解释为什么单个切片的误标率高于 5%，以及任务数增加后它怎样变化 | 1 小时 |
| 5 | 为 run B 设计一个常设监控指标（“只在可见测试上通过”的比例），写出它需要哪些字段、何时报警、会有哪些误报 | 写成半页设计 | 30 分钟 |
| 6 | 把 run C 的退步写成一份给研究员的诊断报告（现象、证据、两个竞争解释、各自需要的干预实验、成本估计） | 报告里每个数字都能追到一条命令的输出 | 45 分钟 |

## 4. 已知问题与修正

- **已修（2026-11-14）**：早先的版本在任务集合变化时返回文字 “task sets differ”，而阻止比较的逻辑只匹配 “differs”，会不加说明地在交集上继续比较。现在可比性问题是结构化的（类型 + `blocking`），处置规则见 [Knowledge §5](../../Knowledge/training_eval_diagnostics/README.md#5-机制诊断的固定路径)。
- 合成数据里没有任务集合变化的情况；这条路径只由自测断言覆盖。

以下各条对应[草图审计](../../Review/mirendil_takehome/草图审计_2026-11-14.md)的编号，均于 2026-11-14 修改并运行了测试。

| 编号 | 问题 | 修正 | 还剩什么 |
|---|---|---|---|
| #22 | 没有任何可比的后续 checkpoint 时，报告一次自己与自己的比较 | 审计前的可比性改造已经修掉；这次补了测试 `test_22_…`，并把提示改成“不报告配对比较、下钻与分解” | 这种情况下训练日志的指标也不打印 |
| #23 | 某切片没有共同有效任务时除以零；整个切片无效时不阻止比较 | 除零此前已修。新增两种可比性问题：`tasks_dropped`（逐个列出退出配对的任务与原因；剩余不足 80% 时阻止）与 `slice_missing`（阻止） | 80% 仍是没有依据的默认值；合成数据里没有这两种情况，只由测试覆盖 |
| #24 | RL 分解忽略 `valid`；用第一条记录的键判断是否 RL run | 分解只用有效且 `reward_pass`、`indep_pass` 都有记录的试验，行尾打印被排除的数量；用 `any(...)` 在整条 run 的记录里找 `reward_pass` | 一条 run 里只有部分记录带 `reward_pass` 时照常分解，只报数量，不判断这是否正常 |
| 怀疑项：窗口不一致 | loss／BPB 报告 1000→4000，通过率比较 1000→3000 | 先定比较窗口，loss、BPB、reward、RL 分解都用它；窗口被缩短时输出 `SHORTENED`，窗口外的值单独列出、标明不参与比较 | — |
| 怀疑项：任务级下降 | 总是打印三个任务，即使全是噪声 | 两行：一行只列单侧 Fisher 精确检验 p < 0.05 的任务（k=3 时最小的 p 正好是 0.05，所以总是 `none`）；一行是标明 `UNFILTERED` 的前三名，带各自的 p，只用来挑样本 | Fisher 检验没有对 40 个任务做校正；k 更大时这一行才有内容 |
| 怀疑项：切片标记的误标率 | 没有真实变化时切片也常被标记 | 输出写明检验了几个切片、标记未校正，并给出 Bonferroni 区间；新增 `--null-sim N` | 实测（2000 个种子）：每切片 7.5%，至少一个标记 26.9%；Bonferroni 后 3.9% 与 14.7%，仍高于 5%，因为 10 个任务上的 percentile bootstrap 区间偏窄。没有换用更合适的小样本区间。审计里的 9.8% 与 34% 没有复现出来，那份模拟的设定没有记录 |

**怎样确认测试有效**：把修改前的 `diagnose.py` 复制到仓库外的临时目录，用 `python3 test_diagnose.py <旧脚本路径>` 运行。修改前的文件上 6 个测试失败（#23 两个、#24 两个、窗口、零假设模拟），`test_22_…` 通过，因为 #22 当时已修。#22 修复之前的版本没有留存；按审计的描述重建（去掉“没有可比 checkpoint 就跳过”的两行）后，`test_22_…` 也失败，输出里出现 `paired diff (step 1000 - step 1000)`。这两份旧脚本只在临时目录里，没有放进仓库。
