# 内容质量与结构选择

## 优先保留的学习体验

定义要说明研究对象，而不仅给同义词。例子要走完，读者能看到输入怎样变成计算、行为或结果。机制要解释为什么，设计要说明在什么条件下做什么选择。

默认中文、必要术语保留英文；先给主要结论，再展开。面向不了解该概念的读者，从定义与例子开始，不先堆公式。对已有基础的读者直接切到卡点，避免重复基础课。

### 深度的四个层面

- **机制**：对象、变量、数据或状态怎样变化，为什么产生结果。
- **设计**：条件怎样决定方案，代价是什么，什么时候换方案。
- **验证**：什么证据支持它，什么反例会推翻它。
- **迁移**：学习例子与真实系统相同和不同的地方。

根据任务选择层面，不要求每段同时满足四层。篇幅不是深度，前沿术语数量也不是深度。

## 结构建议

| 任务 | 合适主线 |
|---|---|
| 新概念／指标 | 定义与对象 → 逐步例子 → 数值或行为直觉 → 应用与局限 |
| 方法／论文 | 研究问题 → 假设与目标 → 机制 → 实现 → 实验和替代解释 |
| 系统设计 | 用户路径与验收 → 组件、接口、状态 → 完整通路 → 错误与验证 → 取舍 |
| 评测研究 | 决策目标 → 测量对象 → 数据与判定 → 对照和统计 → 诊断与下一步 |
| 方案比较 | 判断标准 → 候选方案与证据 → 条件差异 → 选择 → 如何验证选择 |
| 补记 | 简短增量 → 所属章节或文末详解 → 实际问题索引与往返链接 |

这些是组织参考；读者的问题顺序可能更适合另一种结构。

## 数学、代码和例子

有公式时解释符号、取值、单位及关键假设；选能揭露差异的数字，不只展示退化到零的例子。需要训练更新直觉时解释梯度作用到哪里。

有代码时，将必要的变量、shape、mask、detach、状态、接口对应回机制。伪代码、可执行示例、实际执行记录明确区分。只保留解释所需代码，完整实现可另存。

同一例子能降低背景负担时贯穿全文；跨概念硬套同一例子反而混淆时更换。表格用于比较，图用于依赖或流程，不为了格式丰富而增加。

## 文档层次与更新

长文开头提供简短学习结论和导航。给现有材料补记时，优先正文短总结、长解释放相关章节或文末；尊重用户指定位置和原文格式。

实际追问可记录为：原始问题／直觉 → 需要修正的前提 → 机制与例子 → 反例或条件 → 实际影响。新增解释接回对应知识位置，避免堆成无关联聊天转录。

面试用途可增加短回答和追问；普通学习不强制口述稿。闭卷验收和练习完成状态基于实际表现，不能由“讲义写好了”推断“已经学会”。

## 不应采用的捷径

- 用“必须／永远／唯一”替代适用条件。
- 堆论文名、benchmark 名和分数而不解释其意义。
- 将参考材料的长篇口述稿和个人经历当作可直接套用的答案。
- 用同一组自造标签同时调优与证明提升。
- 因为材料内容很多就不断扩充文件与目录。
