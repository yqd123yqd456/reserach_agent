# 知识结构与维护

## 两个入口、四类内容

按知识学习与按公司准备应能访问同一份核心知识。保留已有目录；先查索引和相关文件，再决定归属，不自动批量搬家。

| 内容 | 主要职责 |
|---|---|
| Knowledge | 长期复用的定义、机制、研究方法与技术判断 |
| 公司目录 | 公司调研、JD、面经分析、岗位匹配与当前准备 |
| Practice | 代码、实验、mock、测试结果与错误记录 |
| interview_history | 实际面试的原始记录、回忆、复盘与后续行动 |

这些是逻辑类别，不要求已有项目改成英文同名目录。用户指定路径优先；结构不明确时遵循最近的相关材料，必要时简要说明选择。

## 定位与更新

1. 根据关键词找到相关索引、标题和段落；先小范围搜索，避开依赖、缓存和生成文件。
2. 判定本次是补解释、加应用、修正结论、记录实验，还是新主题。
3. 通用概念优先有一个主要维护位置，可以是长文的一节。公司材料保留其岗位语境和精选解释。
4. 重要主题连接：主要入口、必要先修、易混概念、相关方法、应用、练习与学习状态。用链接或小表足够，不默认搭数据库。
5. 用户要求落盘时更新相应文件及必要索引，检查链接与格式；无关材料保持原样。

## Overlap 的处理

允许为独立阅读重复简短定义、公式和场景例子。不机械去重，也不每次复制整个通用章节。

同名概念在不同场景可能有不同分母、假设与约束，先解释差异再考虑统一。重要知识修正后，检查已知相关片段，更新当前材料或指出尚未覆盖的引用。

历史面试或实验记录保存当时发生的事。新理解附注，不把原有错误回答改写成当时已答对。来源变化保留必要版本语境。

### 示例

通用 recovery evaluation 放在评测知识入口；某公司材料解释它为何与该岗位相关；Practice 保存故障注入实现与实际结果；面试记录保存当时回答与下一次练习。四处可有短定义，但只有一处维护完整方法解释。

## 计划与状态

复习计划负责导航：当前优先项 → 材料／练习位置 → 成果 → 完成标准。当前入口呈现下一轮、最近卡点和下一步，不再复制知识正文。

区分材料已整理、已讨论、在提示下完成、独立完成、通过新题验证。只按实际记录更新状态；过期日期不能自动改为已完成。

普通问答不自动保存；创建 skill 不等于授权整理整个知识库。移动、删除、全库重构和云端同步是单独范围。日常授权的窄范围修改无需反复确认。
