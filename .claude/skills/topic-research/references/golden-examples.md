# 内容参照：候选行为与小片段

这些是人工编写的解释参照与试用目标，不是自动通过的完整标准答案。按主题读取相关片段，不固定全文章节。外部论文和他人笔记仍需核验，不能因写得 hands-on 就当作权威。

## G01 定义与手算

输入：混淆 reward、return、value 与 advantage。

期望：先定义每个量，再给有完整条件的小轨迹。例如三步、终止后价值为零、γ=λ=1，reward 为 `[0,0,1]`，V 为 `[0.5,0.8,0.9]`：TD error 为 `[0.3,0.1,0.1]`，向后累加的 GAE 为 `[0.5,0.2,0.1]`。解释这是这些条件下的结果，不是所有设置都相同；再说明 actor 与 critic 使用什么信号。

验收：换数后能独立计算，能指出简化条件。

## G02 逐步运行

输入：不懂 speculative decoding 为何拒绝一个 token 后丢弃后续 draft。

期望：先给 prompt 与 draft 序列，逐位置写出 target 使用的 prefix，走完接受／拒绝和下一轮；再解释概率校正与端到端加速条件。不能只画两个模型之间的箭头。

验收：改变拒绝位置后能重新推演。

## G03 数学到实现

输入：知道 KL 公式，不懂 sampled-token loss 与 detach。

期望：明确分布与采样来源、加权方向和梯度，连接 tensor、shape、mask 与 detach；用有限差分或独立小算例检查适用实现。不能混淆分布期望的梯度与固定样本上某个 surrogate 的梯度。

验收：能够解释哪些量更新，识别看似合理但目标不一致的代码。

## G04 性质到设计

输入：为什么 agent evaluation 更复杂？

期望：多步 → 终态不足以区分恢复过程；有状态 → 实验单位与初始快照；有副作用 → 执行隔离和状态验证；路径多样 → 约束而非脚本匹配。单轮任务也可能有多解、评分误差和数据依赖，比较不能绝对化。

若用 p^n 例子，声明各步独立、相同可靠性、任一步失败即整题失败且无恢复。实际 agent 不必满足这些条件。

验收：每个结构差异对应一个实际设计或验证动作。

## G05 工程通路

输入：第一次做订单地址修改 agent。

期望：一条用户路径，fake service 中可观察的订单状态、工具参数、代码中的业务规则与审计。覆盖允许修改、已发货拒绝、参数错误或服务失败；真实模型选工具与 fake model 协议测试分开。

验收：能解释输入到状态更新的完整通路，并验证关键边界。

## G06 场景与独立验证

输入：把通用评测方法迁移到文档编辑。

期望：初始文档、用户目标、最终 artifact、结构 diff、语义 rubric、未授权改动检查；提供正确、错误、等价表达和有副作用的结果作为 grader 检查。提案和真实项目经历明确分开。

验收：不靠模型说“完成”推断文档真的改变。

## G07 实际问题与理解变化

输入：连续提出几个 related questions，希望整理学习增量。

期望：保留原始卡点、修正前提、机制、边界与影响；解释写回相关位置，问题索引链接过去。历史记录不改写成当时已掌握。

验收：下次能快速找回卡点并自己回答。

## G08 分层阅读

输入：同一材料用于快速复习与深入学习。

期望：开头少量关键结论，正文有连贯解释，详细推导／代码／补记有清楚位置。允许必要重复，不为压缩而破坏独立阅读。

验收：快速入口能唤回主线，深入部分能支持推理与验证。

## G09 前沿资料影响选择

输入：结合论文、公司技术博客与公开实现研究一个系统问题。

期望：比较问题、约束与证据，指出某项原始发现为何改变方案或实验。多个来源来自同一团队时不算独立验证；最新不自动优于基础方法。

验收：去掉延伸阅读列表后，正文仍能看出研究怎样影响结论。

## G10 挑战“加固后”的参考实现

输入：某 grader 已对 outcome 去重，是否防住刷量？

教学反例：两个真实缺陷已经命中，添加一条重复评论；若 quality 仍逐条加 2.5，重复惩罚为 1，单条成本为 0.5，precision 为独立缺陷数／评论数且门槛为 0.5，则 2/3 仍过门槛，重复评论净增 1 分。

期望：不接受“已经去重”的文字保证，检查所有分项；构造带质量奖励的反例，再考虑按缺陷聚合质量并检查正常案例。以上是人为设定的算例，不是实际模型或生产实验结果。

验收：测试能够揭露具体漏洞；修复不只把当前样例的预期值写死。
